**0.47 のポリシー経路:** コントロールプレーンは `control-keys` ボリュームの Ed25519 鍵でポリシースナップショットに署名します。データプレーンは読み取り専用の `policy-trust` ボリュームの公開鍵で検証し、拒否した場合は最後に検証されたポリシーを維持します。両ボリュームへの書き込み権限を制限してください。[プレーン分離](plane-separation.md)を参照してください。

コンソールは単一テナント Microsoft Entra ID SSO と管理者・閲覧者ロールをサポートします。コンソール運用者の認証とエージェント認可は別の境界で、認可は内蔵 Access Broker が行います。 [Entra SSO](identity.md).

脆弱性の疑いは、リビジョン、合成データによる再現手順、影響を添えて **hellocosmos@gmail.com** へ非公開で報告してください。公開 Issue に顧客データ、トークン、実際の資格情報を含めないでください。固定応答 SLA はありません。

## PII 対応範囲

オフライン検査は、対応ペイロードごとに 6 つの言語プロファイルをすべて評価します。

- 英語：メール、電話番号、クレジットカード、IBAN、米国 SSN
- 韓国語：住民・外国人登録番号、運転免許証番号、旅券番号、事業者登録番号
- 簡体字中国語：電話番号、GB 11643 公民身分番号
- 日本語：電話番号、12 桁の個人番号（マイナンバー）
- スペイン語：電話番号、NIF、NIE、旅券番号
- フランス語：電話番号、コルシカ地域コードを含む NIR 社会保障番号

規格に検査方法がある国別識別子は形式とチェックディジットを検証します。これは決定的なパターン検査であり、汎用 NER ではありません。氏名、場所、住所、画像、OCR、任意ファイルは本リリースの対象外です。

### ポリシー選択と Mirror 証跡

PII 処理は **マッピング済みツール/アクション → ルート → グローバル既定値** の決定的な優先順位を使います。要求で選択されたアクションは、完全にバッファリングされた SSE を含む対応応答本文にも適用されます。証跡にはアクションとスコープだけを記録し、取得した内容は保存しません。Mirror モードでは完全な検出を `would_redact` または `would_block` として保持し、元のバイトは変更しません。不完全な転送または検査だけが `unknown` になります。

## Secret 漏えいの対応範囲

オフライン検査は、認識可能な秘密鍵、一般的な AWS・GitHub・GCP・Slack・Stripe・OpenAI のトークン形式、構造的に有効な署名付き JWT、Azure Storage SAS のクエリ組み合わせ、機密 JSON フィールドの高エントロピー値を遮断します。対応するリクエスト本文、レスポンス、再構成した SSE ストリームに適用します。

リクエストの `Authorization`、cookie、API-key ヘッダーは、署名検証済みで明示的にマッピングされた宛先経路だけで保持し、監査証拠には記録しません。レスポンスヘッダーは検査します。不正な JWT 風文字列、通常の `sig` パラメーター、文書用プレースホルダーは遮断しません。検出記録は取得値を含めず `secret_detected` のみです。決定的検査は新規・独自形式を見逃したり誤検知したりする可能性があります。信頼境界を越えた可能性がある実資格情報は更新してください。

保護境界は、信頼された署名付き転送ホップから明示的にルーティングされた対応 HTTP/MCP 通信です。ローカル例は合成デモであり、強化済み本番装置ではありません。

- 平文、ExtProc、mirror リスナーを信頼ネットワークと送信元に制限します。
- 署名鍵を保護・更新し、エージェントに渡さないでください。上流への経路を強制して迂回を防ぎます。
- inline 検査・認可の失敗は遮断します。別の mirror コレクターは原本を遮断できません。コンソール Mirror は同期経路なので検査器との通信障害時に遮断されます。
- 本文・時間の上限、マッピング、フィールドのマスキングを設定します。バッファ型 SSE は無制限のストリーミングではありません。
- ローカル SQLite の再送防止と監査保存は分散 HA や不変保存を保証しません。
- パターン・PII 検査には誤検知と見逃しがあります。
- 署名された送信元はユーザー・エージェントの本人証明ではありません。Broker モードには別に検証された JWT ID チェーンと明示的 claim mapping が必要です。

初期アカウントは `admin`、パスワードは `1234` です。設定で変更してください。管理はループバックにバインドします。ネットワーク設定は所有するデモ用 Envoy コンテナーを管理し、OS の NIC アドレス、物理経路、ファイアウォール規則は変更しません。認証、CSRF 検査、パスワードハッシュだけで合成デモが本番 IAM になるわけではありません。MIT はランタイムと Access Broker 全体に適用し、顧客資産と credential はリポジトリ外に置きます。
