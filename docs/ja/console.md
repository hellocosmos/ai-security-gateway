## インストールと起動

Python 3.11+、Node.js 22.12+ または 24、npm、稼働中のローカル Docker Engine/Desktop が必要です。このリポジトリだけで導入でき、SDK・非公開ランタイムパッケージ・モデル API は不要です。スクリプトは既存の `uv` を優先し、なければ Python venv/pip を使います。sudo を使わず、Docker はローカルで実行してください。

```bash
git clone https://github.com/hellocosmos/ai-security-gateway.git
cd ai-security-gateway
./scripts/install-console.sh
./scripts/run-console.sh
```

[http://127.0.0.1:5176](http://127.0.0.1:5176) を開きます。初期アカウントは **admin / 1234** です。** 設定 → 管理者パスワード**で変更すると全セッションが無効になります。ループバック限定の評価用インストールであり、インターネット公開用の装置ではありません。ポート競合時は既存サービスを終了せず起動を中止します。Ctrl+C で停止すると、このインストールが所有する Envoy コンテナだけを削除します。

## 言語

ログイン画面または上部バーで選択します。英語が既定で、韓国語・簡体字中国語・日本語・スペイン語・フランス語に対応します。選択はブラウザーに保存され、ログアウトしません。ドキュメントも選択言語で開きます。ツール名・ルールコード・ID・ユーザー入力は翻訳しません。UI 翻訳は PII の対応言語拡張を意味しません。

## 実際の通信経路

```text
Browser -> management API/UI :5176
                 -> signed synthetic sender -> Envoy :18082 -> HTTP destination :18090
                                                 <-> gRPC inspector :18101–18104
                 <- response inspection <- decision + receipt <- UI
```

送信器は信頼済み転送ホップを模擬し、正確な合成リクエストに署名します。TLS 復号器や IdP ではありません。実際の Envoy と独立した HTTP 宛先を使用します。デモは内蔵 Access Broker の実コード、合成 identity、リクエスト結合承認を使い、外部業務処理は行いません。

## 画面と最初の操作

1. **ダッシュボード：** ノート参照、顧客情報マスキング、漏えい資格情報の遮断、削除、指示攻撃、外部送信、応答 PII を実行します。事前入力した判断値ではなく実リクエストからデータを生成します。
2. **トラフィック / イベント：** 絞り込み、HTTP 状態・宛先受信・マスキング・ポリシー版を確認します。CSV は機密情報を除いたメタデータです。
3. **ポリシー：** `notes.read` を遮断にして検証・適用・再実行し、確認後に許可へ戻します。新規ストリームに反映し、処理中のストリームは元のポリシーを維持します。
4. **接続 / システム：** 構成要素と経路を確認します。**監査：** ログイン・ポリシー・ネットワーク変更を確認します。
5. **設定：** ホストのインターフェースを参照し、待受ポート・タイムアウト・本文上限を変更します。Envoy 検証器で確認し、適用時に所有するコンテナを短時間再起動して新ポートを確認します。失敗時は以前の設定を復元します。

## ルート・ツール別 PII ポリシー

グローバル PII アクションが既定値です。HTTP/MCP ルートで上書きでき、マッピングされたアクションまたは MCP ツールでさらに上書きできます。優先順位は **ツール/アクション → ルート → グローバル** で、省略値は継承されます。選択されたアクションとスコープはサニタイズ済みの判断証跡に保存され、対応する応答検査にも使用されます。

**ポリシー → PII オーバーライド** で各デモツールを継承、マスキング、ブロックに設定できます。Mirror モードでは元の要求と応答を変更せず、**許可予定**、**マスキング予定**、**ブロック予定** と表示します。`unknown` は不完全な取得または検査失敗に限ります。Mirror の結果は評価証跡であり、本番での強制実行を証明しません。

## ネットワーク設定と NIC

| 設定 | 既定値 / 意味 |
|---|---|
| 配置 | 明示的 L7、単一ループバック |
| 管理 API/UI | `127.0.0.1:5176` |
| プロキシ入口 | `127.0.0.1:18082`、非特権ポートに変更可能 |
| 検査器 | `127.0.0.1:18101–18104`、gRPC ExtProc |
| 宛先 | `127.0.0.1:18090`、合成 HTTP のみ |
| タイムアウト | 5 秒、2–30 秒で設定可能 |
| 本文上限 | 1 MiB、1 KiB–1 MiB で設定可能 |
| インターフェース | 実ホストの名前・アドレス・リンク状態・MTU・用途 |

インターフェース数にはループバック・ブリッジ・トンネルを含み、物理 NIC 数とは異なります。現在のプロファイルは物理 1/2 NIC ルーティング、透過ブリッジ、OS IP/経路変更、物理送信 NIC 固定を行いません。任意の本番宛先を設定するフォームではありません。macOS は Docker Desktop のホスト転送、Linux はループバック到達のため host networking を使います。Envoy 1.39.1 の amd64/arm64 対応マルチアーキテクチャ digest を固定しています。

## 検査と障害モード

**Inline** は許可・遮断・マスキングを適用し、未マッピング・未署名の要求を拒否します。検査通信の障害時は遮断します。** このコンソールの Mirror** は同じ同期プロキシ経路で内容変更や承認消費を行わず観察し、通信障害時には引き続き遮断します。下位検査器の独立した mirror 収集器はコピーを受信し原本には影響しません。いずれも無制限のリアルタイムストリーム検査ではありません。プロキシ障害時にエンジン直接呼び出しへ退避しません。

## 永続化とトラブル対応

`.runtime-state/console` にアカウント・セッションのハッシュ、ポリシー、ネットワーク設定、機密情報を除いた SQLite イベントを保存します。`TD_CONSOLE_STATE` で別の非公開ディレクトリを指定できます。停止中にバックアップしてください。パス変更は別インストールとなり、この領域は Git から除外されます。署名キーはデモプロセス内の一時キーで、外部転送装置を構成しません。宛先の受信数は再起動時にリセットされますが、保存済み証跡は残ります。監査は編集可能なローカル保存で、不変ストレージではありません。

起動失敗時は Docker、5176/18101–18104/18111–18114/18090 と設定したプロキシポートを確認し、無関係なサービスを自動終了しないでください。検査証跡の欠落は成功ではなくエラーです。遅延はローカル・コンテナの影響を含み、本番ベンチマークではありません。実 TLS・IAM・経路強制・HA・本番強化は別途検証が必要です。

## 検証と翻訳の保守

```bash
.venv/bin/python -m pytest -q
npm run check --prefix console
npm run build --prefix console
# Stop the running console before this Docker test.
TD_CONSOLE_E2E=1 .venv/bin/python -m pytest tests/test_console.py -q
```

`TD_CONSOLE_E2E=1` がなければ Docker テストはスキップします。言語検査では全 6 辞書のキー・プレースホルダーと英語ソースを確認します。英語キーと全 JSON を同時更新し、API コードは変更しません。訳に差異がある場合は英語版を基準とします。[構成](architecture.md)、[エディション](editions.md)、[移行](migration.md)、[セキュリティ](security.md)も参照してください。
