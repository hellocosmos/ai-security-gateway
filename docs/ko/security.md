## PII 지원 범위

오프라인 검사는 지원 페이로드마다 6개 언어 프로필을 모두 평가합니다.

- 영어: 이메일, 전화번호, 신용카드, IBAN, 미국 SSN
- 한국어: 주민·외국인등록번호, 운전면허번호, 여권번호, 사업자등록번호
- 중국어 간체: 전화번호, GB 11643 주민신분번호
- 일본어: 전화번호, 12자리 개인번호(My Number)
- 스페인어: 전화번호, NIF, NIE, 여권번호
- 프랑스어: 전화번호, 코르시카 지역 코드를 포함한 NIR 사회보장번호

국가 식별자는 표준에 정의된 경우 형식과 체크섬을 검증합니다. 이는 결정적 패턴 검사이며 범용 NER이 아닙니다. 이름, 위치, 우편 주소, 이미지, OCR, 임의 파일은 이번 릴리스 범위 밖입니다.

### 정책 선택과 Mirror 증거

PII 처리는 **매핑 도구/작업 → 경로 → 전역 기본값**의 결정적 우선순위를 사용합니다. 요청에서 선택한 작업은 완전히 버퍼링한 SSE를 포함한 해당 지원 응답 본문에도 적용됩니다. 증거에는 작업과 범위만 기록하고 캡처한 내용은 저장하지 않습니다. Mirror 모드에서 완전한 탐지는 `would_redact` 또는 `would_block`으로 유지하면서 원본 바이트는 그대로 전달하며, 불완전한 전송이나 검사만 `unknown`으로 기록합니다.

## Secret 노출 지원 범위

오프라인 검사는 알려진 개인키와 AWS·GitHub·GCP·Slack·Stripe·OpenAI 토큰 형식, 구조적으로 유효한 서명 JWT, Azure Storage SAS 쿼리 조합, 민감한 JSON 필드의 고엔트로피 값을 차단합니다. 지원되는 요청 본문, 응답, 재조립된 SSE 스트림에 적용됩니다.

요청의 `Authorization`, cookie, API-key 헤더는 이미 서명 검증되고 명시적으로 매핑된 목적지 경로에서만 보존하며 감사 증거에는 기록하지 않습니다. 응답 헤더는 검사합니다. 잘못된 JWT 유사 문자열, 일반 `sig` 파라미터, 문서용 placeholder는 차단하지 않습니다. 탐지 결과에는 캡처한 값 없이 `secret_detected`만 기록합니다. 결정적 탐지는 새 형식이나 사내 형식을 놓치거나 오탐할 수 있으므로 신뢰 경계를 벗어났을 가능성이 있는 실제 자격증명은 교체해야 합니다.

보호 범위는 신뢰할 수 있는 서명 홉에서 명시적으로 라우팅한 지원 HTTP/MCP 트래픽입니다. 로컬 예제는 합성 데모이며 강화된 운영 장비 구성이 아닙니다.

- 평문·ExtProc·mirror 리스너는 신뢰 네트워크와 송신자로 제한합니다.
- 서명 키를 보호·교체하고 에이전트에 제공하지 않습니다. 목적지 경로를 강제해 우회를 막습니다.
- inline 검사기나 인가 실패는 차단해야 합니다. 별도 mirror 수집기는 원본을 차단할 수 없습니다. 콘솔 Mirror는 동기 경로이므로 검사기 통신 장애 시 차단됩니다.
- 본문·시간 제한, 매핑, 필드 마스킹을 설정합니다. 버퍼링 SSE는 무제한 스트리밍이 아닙니다.
- 로컬 SQLite 재전송 방지와 감사 저장소는 분산 HA나 불변 보존을 보장하지 않습니다.
- 패턴·PII 검사는 오탐과 미탐이 있습니다.
- 서명된 출처는 사용자·에이전트 신원 증명이 아닙니다. Broker 모드는 별도 검증된 JWT 신원 체인과 명시적 claim mapping이 필요합니다.

콘솔 초기 계정은 `admin`, 비밀번호는 `1234`이며 설정에서 변경합니다. 관리 서버는 loopback에 바인딩합니다. 네트워크 설정은 소유한 데모 Envoy 컨테이너를 관리하며 OS 인터페이스 주소·물리 경로·방화벽 규칙은 변경하지 않습니다. 인증·CSRF 검사·비밀번호 해시가 합성 데모를 운영 IAM으로 만들지는 않습니다. MIT는 전체 runtime과 Access Broker에 적용하며 고객 자산과 credential은 저장소 밖에 둡니다.
