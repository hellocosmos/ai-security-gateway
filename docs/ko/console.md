콘솔은 관리자·조회자 역할의 단일 테넌트 Microsoft Entra ID SSO를 지원합니다. 콘솔 운영자 인증과 에이전트 인가는 별도 경계이며, 에이전트 인가는 내장 Access Broker가 담당합니다. [Entra SSO](identity.md).

## 설치와 실행

필수 환경은 Python 3.11+, Node.js 22.12+ 또는 24, npm, 실행 중인 로컬 Docker Engine/Desktop입니다. 이 저장소만으로 설치하며 SDK·비공개 런타임 패키지·모델 API는 필요하지 않습니다. 스크립트는 설치된 `uv`가 있으면 사용하고, 없으면 Python venv/pip를 사용합니다. sudo 없이 실행하고 Docker는 로컬에서 사용하세요.

```bash
git clone https://github.com/hellocosmos/ai-security-gateway.git
cd ai-security-gateway
./scripts/install-console.sh
./scripts/run-console.sh
```

[http://127.0.0.1:5176](http://127.0.0.1:5176)에 접속합니다. 최초 계정은 **admin / 1234** 입니다. **설정 → 관리자 비밀번호** 에서 변경하면 모든 세션이 종료됩니다. 콘솔은 loopback에만 바인딩하는 로컬 평가용 설치본으로, 인터넷 공개용 장비가 아닙니다. 포트 충돌 시 기존 서비스를 종료하지 않고 시작을 중단합니다. Ctrl+C로 종료하면 이 설치가 소유한 Envoy 컨테이너만 제거합니다.

## 언어 선택

로그인 화면이나 상단에서 언어를 선택합니다. 영어가 기본이며 한국어·중국어 간체·일본어·스페인어·프랑스어를 제공합니다. 선택은 브라우저에 저장되며 로그아웃되지 않습니다. 문서 링크도 선택한 언어로 열립니다. 도구명·규칙 코드·ID·사용자 입력은 번역하지 않습니다. UI 언어 지원은 해당 언어의 PII 탐지 범위 확대를 의미하지 않습니다.

## 실제 트래픽 경로

```text
Browser -> management API/UI :5176
                 -> signed synthetic sender -> Envoy :18082 -> HTTP destination :18090
                                                 <-> gRPC inspector :18101–18104
                 <- response inspection <- decision + receipt <- UI
```

발신기는 신뢰된 전달 지점을 모사해 정확한 합성 요청에 서명하며 TLS 복호화기나 IdP는 아닙니다. 실제 Envoy와 별도 HTTP 목적지를 사용합니다. 데모는 내장 Access Broker에 합성 신원을 등록하고 요청 결합 승인을 실제 코드로 수행하되 외부 업무 동작은 실행하지 않습니다.

## 화면과 첫 사용 순서

1. **대시보드:** 문서 조회·고객 정보 마스킹·유출 자격증명 차단·삭제·지시 공격·외부 전송·응답 PII 시나리오를 실행합니다. 미리 채운 판단값이 아니라 실제 요청으로 데이터를 만듭니다.
2. **트래픽 / 이벤트:** 판단을 필터링하고 상세에서 HTTP 상태·목적지 수신·마스킹·정책 버전을 확인합니다. CSV는 정제한 메타데이터를 내보냅니다.
3. **정책 관리:** `notes.read`를 차단으로 바꾸고 검증·적용한 뒤 다시 실행합니다. 확인 후 허용으로 복원하세요. 새 요청부터 적용하고 진행 중인 스트림은 기존 정책을 유지합니다.
4. **연결 / 시스템:** 구성요소와 실제 경로를 확인합니다. ** 감사 기록:** 로그인·정책·네트워크 변경을 확인합니다.
5. **설정:** 호스트 인터페이스를 조회하고 프록시 수신 포트·제한 시간·본문 상한을 변경합니다. 검증은 Envoy 검증기를 실행합니다. 적용 시 소유한 컨테이너를 잠시 재시작하고 새 수신 포트를 확인하며 실패하면 이전 설정을 복원합니다.

## 경로·도구별 PII 정책

전역 PII 작업이 기본값입니다. HTTP/MCP 경로가 이를 재정의할 수 있고, 매핑한 작업 또는 MCP 도구가 경로 설정을 다시 재정의할 수 있습니다. 우선순위는 **도구/작업 → 경로 → 전역**이며 생략한 값은 상속합니다. 선택된 작업과 범위는 정제된 판단 증거에 저장하고 해당 응답 검사에도 그대로 사용합니다.

**정책 관리 → PII 재정의**에서 데모 도구별로 상속·마스킹·차단을 선택합니다. Mirror 모드에서는 원본 요청과 응답을 바꾸지 않고 **허용 예정**, **마스킹 예정**, **차단 예정**으로 표시합니다. 불완전한 캡처나 검사 실패만 `unknown`으로 남습니다. Mirror 결과는 평가 증거이며 운영 집행을 입증하지 않습니다.

## 네트워크 설정과 NIC

| 설정 | 기본값 / 의미 |
|---|---|
| 배치 | 명시적 L7, 단일 loopback 인터페이스 |
| 관리 API/UI | `127.0.0.1:5176` |
| 프록시 수신 | `127.0.0.1:18082`, 비특권 포트 변경 가능 |
| 검사기 | `127.0.0.1:18101–18104`, gRPC ExtProc |
| 목적지 | `127.0.0.1:18090`, 합성 HTTP 전용 |
| 요청 제한 시간 | 5초, 2–30초 설정 가능 |
| 본문 상한 | 1 MiB, 1 KiB–1 MiB 설정 가능 |
| 인터페이스 | 실제 호스트 이름·주소·링크 상태·MTU·설치 내 역할 |

인터페이스 수는 물리 NIC 수가 아닙니다. loopback·브리지·터널도 포함합니다. 현재 프로파일은 loopback만 사용하며 물리 1·2-NIC 라우팅, 투명 브리지, OS IP/경로 변경, 물리 송출 NIC 고정을 구현하지 않습니다. 임의 운영 목적지를 설정하는 폼도 아닙니다. macOS는 Docker Desktop의 호스트 전달을, Linux는 loopback 접근을 위한 host networking을 사용합니다. Envoy 1.39.1의 amd64/arm64 멀티 아키텍처 digest를 고정했습니다.

## 검사·장애 모드

**Inline** 은 허용·차단·마스킹을 집행합니다. 미매핑·미서명 요청은 거부하고 검사 통신 장애 시 차단합니다. **이 콘솔의 Mirror** 는 같은 동기 프록시 경로에서 본문 변경이나 승인 소비 없이 관찰하며, 검사 통신 장애 시에는 여전히 차단합니다. 하위 검사기의 별도 mirror 수집기는 복사본을 받아 원본에 영향을 줄 수 없습니다. 무제한 실시간 스트리밍 검사로 표현하면 안 됩니다. 프록시 실패 시 엔진 직접 호출로 대체하지 않습니다.

## 영속화와 문제 해결

`.runtime-state/console`에 계정·세션 해시, 정책, 네트워크 설정, 정제된 SQLite 이벤트를 저장합니다. `TD_CONSOLE_STATE`로 별도 비공개 경로를 지정할 수 있습니다. 종료 상태에서 백업하며 경로를 바꾸면 별도 설치가 됩니다. Git에서 제외됩니다. 데모 서명 키는 프로세스 내부의 임시 키이며 외부 전달 장비를 구성하지 않습니다. 목적지 수신 카운터는 재시작하면 초기화되지만 저장한 트랜잭션 증거는 유지됩니다. 로컬 감사 저장소는 수정 가능하며 불변 저장소가 아닙니다.

시작 실패 시 Docker와 5176/18101–18104/18111–18114/18090 및 설정한 프록시 포트를 확인하세요. 관련 없는 서비스를 자동 종료하지 마세요. 검사 증거 누락은 성공이 아니라 오류입니다. 지연은 로컬·컨테이너 영향을 포함하며 운영 성능 벤치마크가 아닙니다. 실 TLS·IAM·강제 경로·HA·운영 강화는 별도 검증해야 합니다.

## 검증과 번역 관리

```bash
.venv/bin/python -m pytest -q
npm run check --prefix console
npm run build --prefix console
# Stop the running console before this Docker test.
TD_CONSOLE_E2E=1 .venv/bin/python -m pytest tests/test_console.py -q
```

`TD_CONSOLE_E2E=1`이 없으면 Docker 검증은 건너뜁니다. 언어 검사에서는 6개 사전의 키·치환자가 일치하고 애플리케이션 코드가 영어인지 확인합니다. 영어 키와 모든 JSON 번역을 함께 수정하고 API 코드는 유지하세요. 번역 간 차이가 있으면 영어 문서를 기준으로 합니다. [아키텍처](architecture.md), [에디션](editions.md), [이전](migration.md), [보안](security.md)도 참고하세요.
