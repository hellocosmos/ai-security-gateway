## PII 支持范围

离线检查会对每个受支持的载荷评估全部六种语言配置：

- 英语：电子邮件、电话号码、信用卡、IBAN 和美国 SSN
- 韩语：居民及外国人登记号、驾驶证号、护照号和企业登记号
- 简体中文：电话号码和 GB 11643 公民身份号码
- 日语：电话号码和 12 位个人编号（My Number）
- 西班牙语：电话号码、NIF、NIE 和护照号
- 法语：电话号码和包含科西嘉地区代码的 NIR 社会保障号

对于标准定义了校验规则的国家标识符，会验证格式和校验位。这是确定性模式检查，不是通用 NER；姓名、位置、邮政地址、图像、OCR 和任意文件不在本版本范围内。

### 策略选择与 Mirror 证据

PII 处理采用确定性优先级：**映射工具/操作 → 路由 → 全局默认值**。请求选中的操作也用于其受支持的响应正文，包括完整缓冲的 SSE。证据仅记录操作和范围，不保存捕获内容。Mirror 模式下，完整检测保留为 `would_redact` 或 `would_block`，原始字节保持不变；传输或检查不完整时才记录为 `unknown`。

## Secret 泄露支持范围

离线检查会阻止已识别的私钥、常见 AWS、GitHub、GCP、Slack、Stripe 和 OpenAI 令牌格式、结构有效且已签名的 JWT、Azure Storage SAS 查询参数组合，以及敏感 JSON 字段中的高熵值。该检查适用于受支持的请求正文、响应和重新组装的 SSE 流。

请求中的 `Authorization`、cookie 和 API-key 头仅在已完成签名验证并明确映射的目标路径上保留，且不会写入审计证据；响应头会接受检查。格式错误的 JWT 类文本、普通 `sig` 参数和文档占位符不会被阻止。检测记录只包含 `secret_detected`，不包含捕获值。确定性检测可能漏掉新格式或自定义格式，也可能误报；任何可能越过不可信边界的真实凭证都应轮换。

边界覆盖来自可信签名转发跳、经过明确路由的受支持 HTTP/MCP 流量。本地示例是合成演示，不是加固后的生产设备。

- 将明文、ExtProc 和 mirror 监听器限制于可信网络及发送方。
- 保护并轮换签名密钥，不向代理提供密钥；强制上游路由以防绕过。
- inline 检查或授权失败必须阻断。独立 mirror 收集器不能阻断原始流量；控制台 Mirror 使用同步路径，检查器通信失败时仍会阻断。
- 配置正文/时间限制、映射及字段脱敏。有界缓冲 SSE 不是无限流式处理。
- 本地 SQLite 防重放与审计存储不保证分布式高可用或不可变保留。
- 特征及 PII 检测可能出现误报和漏报。
- 签名来源不等于用户或智能体身份证明；Broker 模式需要独立验证的 JWT 身份链与显式 claim mapping。
