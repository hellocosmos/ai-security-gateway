网关收集并检查完整的受支持响应后才交付内容。首内容延迟包括收集与检查，不只是扫描时间。适合能等待完整结果的任务；交互聊天需按明确的延迟预算评估。

## 复现

需要 Docker、Python 3.11+ 和项目 console 依赖。命令构建临时栈，不使用真实凭据或付费 API，并在 finally 中删除容器和卷。部署前在空闲主机上至少重复三次。

```bash
python -m pip install -e ".[console,compat,llm-compat]"
python -m examples.latency.benchmark --output /tmp/latency.json
```

## 解读

控制台显示当前进程各阶段最近 256 个样本。网关计时在客户端收到内容之前结束。Envoy 往返包括请求检查、上游收集、响应检查和传输。检查包含工作队列等待。这些分布包含失败，没有逐请求关联，不能相减，重启后清空。无样本表示未测量，不是零。

## 边界

64 个并发请求中完成 32 个，32 个返回 HTTP 503；没有不完整的 HTTP 200 SSE。分片邮件 PII 已脱敏。测试专用 32 KiB 限制下，超大输出返回 HTTP 500，10 秒超时返回 504，均无内容令牌。无效凭据返回 401。状态码不能单独定位故障组件，生产默认值不同。

## 0.45 逐请求延迟与准入

控制台显示当前进程最近 64 个完成的网关请求时间线。每行仅保存数值时间、HTTP 状态和完成标记。签名随机 ID 仅用于内部关联适配器和检查器，不在界面显示。不保存正文、路径、凭据或代理身份。早期认证和准入拒绝显示在网关结果中。

分别展示检查流等待、工作队列等待和执行时间。响应正文等待从元数据检查结束到缓冲正文到达检查器，包含上游生成、传输和 Envoy 缓冲。区间可能重叠或有传输空隙，不能相加或视为纯模型延迟。重启后清空。

`gateway_max_inflight` 仅接受整数 4–64，默认仍为 32。通过暂存和维护重启应用，连接向导保留此设置。超额请求返回 HTTP 503。较小值仅适合能够接受更多拒绝而重视较低延迟的任务。合成比较中，48 未增加突发完成量且出现 HTTP 500。

一次合成运行无法给所有环境定值。重现下表，再在目标主机上按典型响应、并发、提供商配额和首内容/完成延迟预算验收。

### 本地合成对比（2026-09-22）

每个设置重复两次，使用延迟的 32 段 SSE 测试服务、32 KiB 正文限制、16 个检查流和 4 个检查工作线程。并发 32 时每次发送 64 个请求，并发 64 时每次发送 128 个请求。首内容 p95 范围仅统计并发 32 时完整的 HTTP 200 响应。

| 网关上限 | 并发 32 完成 | 首内容 p95 | 并发 64 完成 | 并发 64 的 HTTP 500 | 应用 CPU / 内存采样峰值 |
|---:|---:|---:|---:|---:|---:|
| 8 | 每次 8/64 | 1.16–1.18 秒 | 每次 8/128 | 0 | 62% / 116 MiB |
| 16 | 每次 16/64 | 1.53–1.54 秒 | 每次 16/128 | 0 | 110% / 127 MiB |
| **32（默认）** | **每次 64/64** | **3.02–3.10 秒** | **每次 32/128** | **0** | **118% / 148 MiB** |
| 48 | 每次 64/64 | 2.96–3.06 秒 | 每次 32/128 | 13–16 | 124% / 161 MiB |
